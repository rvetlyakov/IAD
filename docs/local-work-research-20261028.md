# Локальное исследование ГА — 28 октября 2026

Расчёт выполнен на Mac пользователя, без ожидания GitHub Actions.
Основная серия: **3670 завершённых запусков за 362,36 с**. Дополнительно
выполнены 27 корректирующих измерений активного интервала миграции:
всего **3697 исследовательских запусков**, включая 27 архивных.
Отдельные проверки ускорения и шесть воспроизведений не входят в эти числа.

## Результат на независимом контроле

| Класс | Запусков на вариант | Только 2-swap: ошибка | 2-swap + 3-cycle: ошибка | Островной + 3-cycle: ошибка | Время обычного / островного |
|---|---:|---:|---:|---:|---:|
| Малые, n<100 | 9 | 76,66% | 17,56% | 10,83% | 37,0 / 25,3 мс |
| Средние, 100–499 | 9 | 125,47% | 29,55% | 29,05% | 22,8 / 20,3 мс |
| Большие, 500–2000 | 18 | 69,05% | 6,34% | 5,80% | 214,6 / 331,2 мс |

Ошибка: 100 × (стоимость ГА − точный оптимум) / точный оптимум.
Это средние по реально измеренным контрольным матрицам. Разброс, максимумы
и доля точных решений приведены в `holdout_summary.csv`.

Краткие выводы для презентации:

1. **3-cycle существенно уменьшает ошибку средних задач:** с 125,47% до
   29,55% в парной абляции с одинаковыми остальными настройками. Улучшение
   требует дополнительной вычислительной работы; точность всё ещё не идеальна.
2. **Острова не гарантируют ускорения.** На больших задачах они дали немного
   меньшую ошибку, но среднее время выросло примерно в 1,54 раза. Близкие
   средние малых/средних не являются доказательством статистической значимости.
3. **Чистый RSS + инверсия без локального поиска существенно слабее** на этой
   серии. Он сохранён как отдельная абляция; его нельзя смешивать с гибридом.
4. **Большие случайные матрицы здесь могут быть относительно легче:** при
   A[i,j]∈1…100 ожидаемое число единиц в строке равно n/100. Поэтому падение
   относительной ошибки с n не доказывает общего улучшения масштабируемости.
5. Все 12 диагональных запусков нашли стоимость n. Это проверка корректности,
   а не доказательство точности на произвольных матрицах.

Для средних TRAIN предпочёл один остров. Четыре острова — лучший проверенный
действительно параллельный кандидат, а не замена этой рекомендации по HOLDOUT.

## Методика и ограничения

- 616 TRAIN запусков на 12 независимых матрицах: по два размера и две
  матрицы на размер каждого класса. Один проход координатного подбора:
  изменяется один фактор, остальные фиксированы внутри сравнения.
  Все проверенные уровни и контексты записаны в CSV. Это ограниченный поиск,
  а не глобальный оптимум и не доказательство оптимальности каждой координаты
  после изменения последующих параметров.
- Затем настройки заморожены. SURVEY: 2898 измерений на 46 новых матрицах:
  10–90 с шагом 10; 100–475 с шагом 25; 500; 550–950 с шагом 50;
  1000–2000 с шагом 100. По одному запуску на размер и значение фактора.
  20 факторов исследованы отдельно, включая 1/2/4/8 островов.
- Условные параметры исследованы в явно включённом фиксированном контексте:
  ранговый RSS для степени рангов, адаптация для её управляющих полей,
  ненулевая миграция для её интервала. 27 первоначальных неактивных замеров
  интервала малых задач сохранены отдельно, заменены новыми измерениями
  при фиксированной доле 0,1 и не используются на итоговых графиках.
- HOLDOUT: 36 новых матриц, четыре варианта, 144 запуска. По три независимые
  матрицы на каждый контрольный размер. Настройки по этому набору не выбирались.
- TRAIN, SURVEY, HOLDOUT и диагональные матрицы имеют непересекающиеся seed.
  SciPy `linear_sum_assignment` вычисляет только эталон. ГА его не вызывает.
- В паре обычный/островной совпадают общие N, G, настройки мутации и локального
  поиска и **фактическое глобальное число локальных вызовов**. Одинаковость
  числа вызовов не означает одинакового числа выполненных внутренних операций.
- Время включает инициализацию ГА, передачу матриц процессам и миграцию;
  исключает SciPy, прогрев JIT и создание переиспользуемого пула. Прогрев
  измерен отдельно. Это реальные времена на данном Mac, без контроля фоновой
  нагрузки и без статистического доказательства ускорения.

## Исполнение и проверки

2-swap и 3-cycle ускорены Numba с сохранением Python-референса. Сверка дала
одинаковые перестановки и количество улучшений. В отдельной диагностике
локальные функции ускорились примерно в 137–158 раз; это не ускорение всего ГА.
Четыре разных процесса действительно работали одновременно: в
`execution_probe.json` сохранены 42 перекрывающиеся пары интервалов работы.
Свежий и прогретый пул дали одинаковое решение. Шесть контрольных случаев
на финальном коде точно воспроизвели первоначальные стоимости.

Исправлен крайний случай квот: при неодинаковом размере островов и локальном
бюджете, охватывающем всю популяцию, раньше терялись вызовы (26 вместо 28 в
регрессионном примере). Остаток теперь перераспределяется. Этот крайний
режим не встречается ни в одной строке опубликованной серии.

Аудит проверяет OFAT, разделение seed, все размеры/уровни, пересчитанные
эталоны SciPy, ошибки, бюджеты, PID процессов, миграции и диагональные решения.
Каждая выполненная строка сохранялась немедленно после проверки перестановки.
Ruff также исправил существовавшие неиспользуемые импорты и замечания стиля.

```bash
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python -r requirements.txt
OPENBLAS_NUM_THREADS=1 .venv/bin/python lab1/local_research.py --output results/new_local_run
# Для старта с уже измеренного набора:

.venv/bin/python lab1/local_replay.py
```

дописывать дубликаты в уже существующие таблицы этапа.
Старый Actions run 40591351661 остановлен; автоматические проверки по
расписанию не включались.
