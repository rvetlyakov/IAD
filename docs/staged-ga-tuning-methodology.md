# Поэтапный подбор ГА: сначала гиперпараметры, потом однофакторные графики

## Почему прежний подбор требовал пересмотра

Прежние таблицы подобрали для среднего класса всего **100 поколений** и
`local_candidates=8`, а для больших — 500 поколений и 16 кандидатов.
Поэтому средняя ошибка у среднего класса могла быть выше, чем у большого,
несмотря на меньшую матрицу. Это не математическая ошибка в формуле
`100*(C_GA-C_opt)/C_opt`: сравнивались разные вычислительные бюджеты,
разные конфигурации и распределение относительной ошибки.

**Нельзя специально ухудшать большие матрицы ради красивого графика.**
Снижение ошибки с ростом n также не обязано быть монотонным из-за
изменения оптимальной стоимости, свойств случайной матрицы и
отдельных стохастических запусков.

## Новые классы без пересечений

- **Малые:** 2 ≤ n < 100.
- **Средние:** 100 ≤ n < 500.
- **Большие:** 500 ≤ n ≤ 2000.

Это исключает дублирование на границах 100 и 500. Матрицы 0×0 и 1×1
для настройки ГА не используются; 1×1 тривиальна и проверяется отдельно.
Размерности в новом обзоре:
малые 10,20,…,90; средние 100,125,…,475;
большие 500,625,…,2000.

## Три независимых этапа

**А. Обучение рабочих настроек.** На нескольких тренировочных
размерностях и двух независимых матрицах выполняется полный перебор
комбинаций G (поколений) и K (числа кандидатов локального поиска).
У средних матриц поколения **100,250,500,750,1000**,
K = 8,16,32. При этом все остальные настройки зафиксированы.
Далее последовательный координатный подбор рассматривает
все остальные активные настройки по одной, затем отдельно число
островов и миграцию. Всё это — **только TRAIN**.

**Коррекция адаптивной мутации.** Её скорость убывания теперь задаётся
самостоятельным параметром `adaptive_horizon`, а не `max_generations`.
Иначе изменение только количества поколений одновременно меняло бы
длину мутации во всех первых поколениях — это был бы методический
конфаундер. Новый параметр тоже можно исследовать отдельно. Поэтому
старые кривые для адаптивной мутации не объявляются результатами
исправленной версии и хранятся отдельно.

**Б. Проверка влияния гиперпараметров.** Выбранная конфигурация
замораживается; меняется только один параметр. Для зависимых
настроек фиксируется осмысленный контекст: например, rank_power
исследуется при rank RSS, период миграции — на островном ГА.
Сырые данные каждого запуска содержат `context_json`
и `settings_json`. Источники фактических точек — SURVEY-матрицы,
которые не участвовали в обучении.

**В. Независимая оценка.** Ещё несколько матриц и seeds,
не использовавшихся ни при обучении, ни при построении OFAT-графиков.
Сравниваются исходная и выбранная конфигурации; одиночная
и островная после настройки. Размеры популяции и числа поколений
сохраняются в парных островных проверках.

## Графики

`lab1/staged_charts.py` строит отдельные PNG/SVG:
ошибка и время каждого гиперпараметра, оси, легенда и реальные точки.
PCHIP используется только внутри одного класса, без выдуманных
измерений или соединений разных классов, настроенных отдельно.
Заголовки слайдов и правые поясняющие блоки не встраиваются.

## Команды

```bash
python -m unittest discover -s tests -p test_staged_tuning.py -v
python lab1/staged_tuning.py --class-name medium --stage train
python lab1/staged_tuning.py --class-name medium --stage refine
python lab1/staged_tuning.py --class-name medium --stage ofat
python lab1/staged_tuning.py --class-name medium --stage holdout
python lab1/staged_charts.py
```

По завершении измерений смотрим результаты в
`results/staged_tuning_v2/`. **До фактического завершения новых
экспериментов прежняя таблица best_observed_config.json остаётся
историческим результатом**, а новая конфигурация не объявляется лучшей.

## Ограничения

Глобальный максимум качества не имеет смысла без ограничения
вычислительного бюджета: например, 1000 поколений может уменьшить
ошибку ценой большего времени, а лучшие настройки из ограниченного
набора не являются глобальным математическим оптимумом.
Опубликованные однофакторные кривые сохраняют один SURVEY-seed
на размерность — для статистической уверенности в близких значениях
нужны дополнительные повторы.
