# Алгоритм для описания в презентации

Задача: назначить каждому работнику ровно одну работу, используя каждую
работу один раз и минимизируя суммарную стоимость.

Хромосома — перестановка π столбцов. Стоимость решения:

**C(π) = Σ A[i, π(i)].**

1. Создать N случайных допустимых перестановок.
2. С вероятностью p выполнить инверсию случайного непрерывного фрагмента.
   Максимальная длина определяется процентом от n, но составляет не менее 2.
   Родители сохраняются в пуле кандидатов вместе с мутантами.
3. В заданные поколения выбрать особей для локального улучшения. В новом
   режиме выбираются реальные инверсионные потомки. При отсутствии потомков
   используется выбор лучших кандидатов.
4. Выполнить направленные парные обмены назначений и, если включено,
   тройные циклические обмены. Каждый локальный обмен принимается только
   при строгом уменьшении стоимости; перестановка остаётся допустимой.
5. Применить RSS или ранговый RSS с сохранением заданной доли элиты.
   Следующая популяция снова содержит ровно N особей. Сохранить лучшее
   посещённое решение независимо от его попадания в следующую популяцию.
6. Повторять до заданного числа поколений G.

```mermaid
flowchart LR
    A[Случайные перестановки] --> B[Инверсионная мутация]
    B --> C[Локальное улучшение потомков]
    C --> D[RSS и элитизм]
    D --> E[Следующее поколение]
    E --> B
    E --> F[Лучшее найденное решение]
```

В островном варианте общая популяция N распределяется между островами.
Острова эволюционируют в отдельных процессах; после заданного интервала
лучшие особи передаются следующему острову по кольцу. Размеры островов
после миграции сохраняются. Общая квота локальных улучшений распределяется
между островами, а не умножается на их число.

При исследовании точный оптимум вычисляется отдельно через
`scipy.optimize.linear_sum_assignment`. Он нужен для оценки ошибки и
не используется для построения или улучшения решений ГА.

Исследуемая реализация использует мутацию, отбор и элитизм без скрещивания.
Локальный поиск делает её гибридным эволюционным алгоритмом. Этот вариант
следует явно отличать от исходного RSS + инверсия без локального поиска.
